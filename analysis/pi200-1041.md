# PI-200 — UDP 1041

## What it is

PI-200 (AK-PI 200) is Danfoss's IP↔Danbuss gateway/discovery protocol. The firmware opens UDP 1041
(`Firewall setup eth0 for PI200 (1041) port`) and `sm_app` runs it from `Init_PI200_port`
(`IP/UDP Channel PI200`, `os_ip_bind`). It is a broadcast discovery/scan protocol: the manager
queries the segment and enumerates nodes.

Relevant symbols in `sm_app`:

```
Init_PI200_port         PI200_send_query        PI200_send_msg_rescan    PI200_rescan_all
PI200_post_received_msg Broadcast_query_new_nodes  Broadcast_receive_handler  ak2_handlePI200
TFN_Build_scan_PI200_list  TFN_Get_PI_200_Status   TFN_Rescan_show_PI200
```

Channel message labels: `CHAN_PI200_QUERY`, `CHAN_PI200_VERIFY`, `AK2_PI200_NW_LIST_RESP`,
`AK2_PI200_MSG_APPEND`.

## The query frame (recovered)

Disassembly of `PI200_send_query` (ARM) shows it builds a `sockaddr_in` for **udp/1041**
(`htons(1041)`), then calls `os_ip_sendto` with a **64-byte** datagram from a pre-built template,
retried up to 3× (100 ms apart):

```
5cb348:  movw r0, #1041            ; htons(1041)  -> sin_port
5cb38c:  mov  r3, #64              ; datagram length = 64
5cb394:  bl   os_ip_sendto
```

So a PI-200 discovery query is a **64-byte** UDP datagram to port 1041. The decoy flags inbound
64-byte datagrams as `pi200_query` (others as `pi200`) and logs the payload head — but sends **no
reply**.

## The node record — `eth485_node` (128 bytes)

Node/device records travel as the `eth485_node` struct (DWARF layout in
[`structs/eth485_node.txt`](structs/eth485_node.txt)):

```
offset  field
  0     UINT16  protocol_version
  2     UINT16  software_version
  4     UINT8   type
  5     UINT8   status
  6     UINT16  seq
  8     UINT8   command
  9     UINT8   number_of_units
 10     UINT16  local_address
 12     UINT32  ip_address
 16..24 UINT32  internet_address1..3
 28     UINT16  port_number
 30     UINT16  internet_port
 32     UINT8   logger
 33     UINT8   store_name[31]
 64     UINT8   unit_name[31]
 95     UINT8   spare[30]
125     UINT8   checkbyte
        (size: 128)
```

## Why the decoy does not reply

The query shape (64 bytes) is known and the node-record layout (128 bytes) is known, but the
**response envelope** — how a node wraps its `eth485_node` into an `AK2_PI200_NW_LIST_RESP` reply —
is not recoverable from the binary without tracing the asynchronous Orion-bus response path, and a
UDP capture would require a live device. Emitting a reply with a guessed envelope would be inventing
a protocol. Per the decoy's rules (never fabricate a protocol; a wrong reply is a worse tell than a
quiet port), PI-200 decodes and flags but does not respond.
